Lago Data Pipeline lets you automate the flow of your billing, subscription, and usage data into your analytics and storage systems.
Use it to run queries in your warehouse or to build dashboards for your finance team from data that stays in sync.

## Prerequisites
- **Data sync frequency:** 1 day by default, but we can go down to 15 minutes;
- **Data transfers:** Incremental or Backfill; and
- **Data security:** a high level of security and encryption.

## Data sources
Lago syncs one dataset to your destination, whichever billing engine your organization uses: plans and subscriptions, or the product catalog with contracts and rate cards.
The table names, column names and their meaning are the same for both, so an organization that moves to the product catalog keeps the same tables and queries.

- Tables that only apply to one billing engine are synced for every organization, and are empty when your organization does not use that engine. For example, the product catalog tables below are empty for an organization billing with plans and subscriptions.
- Tables used by both billing engines, such as `fees` and `daily_usages`, have additional columns for the product catalog. These columns are always added after the existing ones and are empty for rows that do not come from the product catalog. Existing columns are never renamed, removed or reordered.

Every table has an `organization_id` column, a `lago_id` primary key and an `updated_at` column used for incremental syncs.

## Product catalog columns

### Columns added to `fees`

These columns come after the existing `fees` columns. They are empty for fees billed from plans and subscriptions.

| Column                       | Type   | Description                                       |
|------------------------------|--------|---------------------------------------------------|
| `lago_contract_id`           | string | Contract the fee was billed for.                  |
| `lago_contract_rate_card_id` | string | Contract rate card the fee was billed from.       |
| `lago_rate_card_rate_id`     | string | Rate card rate applied to compute the fee.        |
| `lago_product_filter_id`     | string | Product filter the fee applies to, if any.        |
| `lago_product_id`            | string | Product the fee was billed for.                   |

For product catalog fees, the existing `item` column has the type `product` with the product's code and name, and `lago_customer_id` is the customer of the contract.

### Columns added to `daily_usages`

These columns come after the existing `daily_usages` columns. A row holds the daily usage of either a subscription or a contract: subscription columns are empty for contract rows, and contract columns are empty for subscription rows.

| Column                       | Type   | Description                                         |
|------------------------------|--------|-----------------------------------------------------|
| `lago_contract_id`           | string | Contract the usage belongs to.                      |
| `external_contract_id`       | string | External id of the contract.                        |
| `lago_contract_rate_card_id` | string | Contract rate card the usage is tracked for.        |

For contract rows, the entries of `daily_usage` reference a contract rate card instead of a charge.

## Deleted records

The sync only adds and updates rows in your destination, so deletions in Lago are exported as data:

- When a table keeps deleted records, the row is still synced and its `deleted_at` column holds the deletion date. Filter on `deleted_at IS NULL` to keep active records only.
- When a record is removed from Lago, a row is added to the `record_deletions` table with the name of its table in `table_name` and its id in `lago_record_id`. Delete or ignore the matching rows in your destination.

`record_deletions` covers the following tables: `fees`, `fees_taxes`, `invoice_subscriptions`, `invoices_taxes`, `credit_notes_taxes`, `billing_entities_taxes`, `customers_taxes` and `rate_cards_taxes`.
