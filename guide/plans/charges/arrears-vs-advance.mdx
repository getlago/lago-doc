---
title: "Arrears vs Advance"
description:
  "Usage-based charges can be either charged in advance or in arrears"
---

You have the flexibility to define the nature of charges associated with your products or services. Specifically, you can 
**determine whether a charge has to be paid in arrears (at the end of the period), or in advance (immediately on event ingestion)**.


## Charges paid in arrears
Charges settled in arrears are invoiced at the end of the billing period, based
on the actual usage during that period. This suits usage types like storage, API
calls, or compute, where it is more practical to wait until the end of the
period before billing. By default, all charges are billed in arrears.

  <Tab title="API">
    Set `pay_in_advance` to `false` on a charge to bill it in arrears:
    <CodeGroup>
      ```bash Define a charge as paid in arrears {16, 22}
          LAGO_URL="https://api.getlago.com"
          API_KEY="__YOUR_API_KEY__"

          --header 'Content-Type: application/json' \
          --data-raw '{
            "plan": {
              "name": "Premium",

              "interval": "monthly",
              "description": "Premium plan for SMB companies",
              "amount_cents": 50000,
              "amount_currency": "USD",
              "trial_period": 0.0,
              "pay_in_advance": true,
              "bill_charges_monthly": true,
              "charges": [
                {
                  "billable_metric_id": "1111_2222_3333_4444",
                  "charge_model": "percentage",
                  "pay_in_advance": false,
                  "invoiceable": true,
                  "min_amount_cents": 100,
                  "properties": {
                    "rate": "0.5",
                    "fixed_amount": "1",
                    "free_units_per_events": 3,
                    "free_units_per_total_aggregation": null
                  }
                }
              ]
            }
          }'
      ```
    </CodeGroup>

## Charges paid in advance
Charges paid in advance are invoiced immediately when usage changes. Use this
when you need to bill a customer instantly for a usage-based action, such as
adding a user seat or an integration.
