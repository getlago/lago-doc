Open your application repository in a coding agent. This guide takes you from your pricing rules to a working Lago integration: decide what to bill, add the code, then compare what Lago recorded with the amount you expected. You can plan and test the code locally before you have a Lago account.

[Choose your agent and install Lago](/guide/ai-agents/for-agents#pick-your-agent). Your application will use a [Lago SDK or REST API](/api-reference/intro) to send customers, subscriptions, and usage. The [Lago CLI](/guide/lago-cli/overview) helps you set up Lago and check the result.

## 1. Map billing in your application

Paste this into your agent, replacing the pricing placeholder:

```text
Inspect this app and current Lago docs. We charge [describe your pricing].
Show who pays, what creates billable usage, how billing works today, and
one example bill. Propose the smallest Lago integration and flag any
double-billing risk. Do not edit code or connect to Lago yet.
```

Review the proposed price, example bill, and treatment of existing customers before asking the agent to implement them. If another system already bills those customers, decide which customers will move to Lago and when.

## 2. Build and test locally

Once you accept the agent's billing plan, ask it to build the first change:

```text
Implement the billing change we agreed on in this repository. Use a Lago SDK
or the REST API from server-side code. Add local tests for the example bill
and for retrying the same usage event. Preserve existing billing unless we
explicitly agreed to change it. Show the code diff and test results before
sending anything to a live Lago organization.
```

Each usage event should get its `transaction_id` from the app record created when the usage happened. Save that record's original timestamp so a retry reuses **both** the same ID and timestamp; both matter for duplicate protection on ClickHouse-based event pipelines. See [idempotency and deduplication](/guide/events/ingesting-usage#idempotency-and-deduplication).

## 3. Connect to the right Lago organization

You need an organization and API key for live CLI or API requests:

- **Lago Cloud:** Ask your team's Lago admin for an invitation. If you need a new organization, [request access from Lago](https://getlago.com/book-a-demo); Lago's team sets up Cloud accounts. Confirm whether your organization is in the US or EU region.
- **Self-hosted Lago:** Use your team's instance or [deploy Lago](/guide/lago-self-hosted/overview). If you deploy it yourself, sign up in its web app to create an organization. Get the API service's base URL from your operator or deployment, for example `https://lago.example.com` (without `/api/v1`).

Get the API key from **Developers → API keys** in that organization, or ask an admin to provide one. Make it available to your terminal as `LAGO_API_KEY`; keep it out of prompts and source control. Install the CLI where you run your agent:

You can ask your agent to handle the setup without giving it the key in chat:

```text
Set up the Lago CLI in this development environment. Check my operating
system and whether the CLI is already installed. Tell me how to set
LAGO_API_KEY in my terminal or secret manager without pasting it into chat,
printing it, or saving it in this repository. Ask whether my target is
Lago Cloud US, Lago Cloud EU, or a self-hosted API URL. Then run lago version,
lago init with the environment variable, lago whoami, and lago doctor.
Show me the API host and organization you connected to. Stop if either is
different from the one I intended. Do not create or change billing data.
```

```bash
brew install getlago/tap/lago
lago version
```

On other systems, use the [CLI release archives](https://github.com/getlago/lago-cli/releases). Connect to your target:

<CodeGroup>

```bash Cloud US
lago init --api-key "$LAGO_API_KEY" --region us
```

```bash Cloud EU
lago init --api-key "$LAGO_API_KEY" --region eu
```

```bash Self-hosted
lago init --api-key "$LAGO_API_KEY" --region self-hosted \
  --api-url https://lago.example.com
```

</CodeGroup>

For self-hosted Lago, `--api-url` must point to the API service if its address differs from the web app. Confirm the organization and host before changing any billing configuration:

```bash
lago whoami
lago doctor
```

A CLI dry run sends nothing. Lago does not create a sandbox inside an organization. Use a separate test organization or an isolated self-hosted instance for live tests; do not add demo customers or plans to a shared production organization.

### Configure your metric and plan

Have the agent inspect existing Lago metrics and plans before proposing changes:

```bash
lago billable-metrics list --limit 50
lago plans list --limit 50
```

Ask it to show the proposed metric and plan as dry runs. For example:

```bash
# Illustrative metric; use your product's actual name, code, and aggregation.
lago billable-metrics create --name "Completed jobs" \
  --code completed_jobs --aggregation-type count_agg --dry-run
# After your agent writes this plan file:
lago plans create --input @billing/lago-plan.json --dry-run
```

Check the API URL, currency, base amount, included usage, overage price, and effective dates before a live write. `--dry-run` shows the request; it does not compare it with existing Lago configuration. A plan charge needs the **actual metric ID** after metric creation. See the [metric](/guide/lago-cli/commands/billable-metrics) and [plan](/guide/lago-cli/commands/plans) command references.

## 4. Check what Lago recorded

Choose one customer and billing period. First calculate the expected charge from your application's own usage records and pricing rules. Then read Lago's current usage for that customer's subscription:

```bash
lago customers current-usage "$CUSTOMER_EXTERNAL_ID" \
  --external-subscription-id "$SUBSCRIPTION_EXTERNAL_ID" \
  --output json
```

Compare the quantity and usage charge with your calculation. If the first read shows zero, wait for processing and read again rather than sending another event. In an isolated test environment, retry one event with its original `transaction_id` and `timestamp`; confirm that the charge does not increase.

If your organization has Premium, [preview the invoice](/guide/invoicing/previews) and compare the base charge, usage charge, credits, taxes, and total. Invoice preview is also Premium on self-hosted Lago. A successful event response or passing local test does not by itself prove the bill is correct. The [integration testing guide](/guide/integration-testing) covers the rest of the billing lifecycle.

For usage retries, prepaid credits, a self-hosted connection, or a billing mismatch, choose a prompt from [More prompts](#more-prompts) below.

## Optional: practice on a sample application

If you want to try the workflow before touching your own code, use the [growth-agent billing lab](https://github.com/anhtho-lago/growth-agent-billing-lab/tree/codex/lago-agent-doc-example). It is a small synthetic app that tracks customer credit usage but does not send it to Lago. The exercise is to add that integration and test the amount without contacting a live Lago organization.

```bash
git clone --branch codex/lago-agent-doc-example \
  https://github.com/anhtho-lago/growth-agent-billing-lab.git
cd growth-agent-billing-lab
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Open the sample in your agent and use its [credits-and-overage prompt](https://github.com/anhtho-lago/growth-agent-billing-lab/blob/codex/lago-agent-doc-example/prompts/credits-and-overage.md). The [sample pricing rules](https://github.com/anhtho-lago/growth-agent-billing-lab/blob/codex/lago-agent-doc-example/BILLING_BRIEF.md) are \$500 per month with 50,000 included credits, then \$0.05 per extra credit. At 75,000 credits, the expected charge is **\$1,750 before tax**: \$500 base plus \$1,250 in extra usage.

To compare that result with an isolated self-hosted Lago instance, follow the sample's [verification instructions](https://github.com/anhtho-lago/growth-agent-billing-lab/blob/codex/lago-agent-doc-example/README.md#verify-usage-in-isolated-self-hosted-lago). They include the fixture, retry check, and optional Premium invoice preview. Run the fixture only on an isolated instance with no real customers or payment provider; `--mode test` is a label, not a sandbox. Use the [evaluation rubric](https://github.com/anhtho-lago/growth-agent-billing-lab/blob/codex/lago-agent-doc-example/evals/README.md) to record what your agent actually proved.

## If the result differs

| Symptom | First check |
| --- | --- |
| `lago` runs Docker Compose | Run `lago version`; remove a self-hosted shell alias shadowing the CLI. |
| Authentication or wrong organization | Run `lago doctor` and `lago whoami`; verify API host and key. |
| Event exists but usage is zero | Check the subscription's active period, metric code, event timestamp, and aggregation property. |
| A retry increases usage | Compare both the original `transaction_id` and explicit `timestamp`. |
| Usage or preview differs from expected money | Check the plan charge, billing period, customer overrides, taxes, credits, and whether the base fee was billed in advance. |
