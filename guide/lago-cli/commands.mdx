Commands follow one shape:

```bash
lago <resource> <action> [identifier] [flags]
```

Every command answers `--help` with its full flag list. The rules that apply everywhere:

- **Flags are API fields.** A `snake_case` field becomes a `--kebab-case` flag. Nested fields are prefixed with their parent: `billing_configuration.payment_provider` is `--billing-configuration-payment-provider`.
- **Objects and arrays take JSON.** `--metadata '[{"key":"tier","value":"gold","display_in_invoice":false}]'`.
- **`--input` takes the whole body.** Inline JSON or `@file.json`. It is the right tool for deeply nested payloads such as plan charges. The body is wrapped exactly as the API expects it.
- **Identifiers are positional**, and their kind depends on the resource. Mixing kinds produces a not-found error that names the resource type and exits 4.

| Resource | Positional identifier |
| --- | --- |
| customers, wallets `*-customer`, payment methods | `external_customer_id` (yours) |
| subscriptions | `external_id` (yours) |
| billable metrics, plans, coupons, add-ons, taxes, features, billing entities | `code` |
| invoices, credit notes, fees, payments, payment requests, wallets, webhook endpoints, quotes, orders | `lago_id` (Lago's UUID) |
| events | `transaction_id` |

The [overview](/guide/lago-cli/overview) covers the global flags (`--output`, `--query`, `--dry-run`, `--confirm`, `--profile`), output contracts, and exit codes. This page is about the commands.

## Setup and diagnostics

| Command | Description |
| --- | --- |
| `lago init` | Configure a profile. Validates the key before saving. |
| `lago whoami` | Show the active profile, organization, and resolved API host. |
| `lago doctor` | Check configuration, permissions, network, and authentication. |
| `lago version` | Show the CLI version and the embedded OpenAPI spec version. |
| `lago upgrade` | Print the upgrade command for how the binary was installed. |
| `lago completion <shell>` | Print a completion script for `bash`, `zsh`, `fish`, or `powershell`. |

<CodeGroup>

```bash init
# Cloud US, test profile
lago init --api-key "$LAGO_API_KEY" --region us --mode test

# Cloud EU, named profile
lago init --profile eu-prod --api-key "$LAGO_API_KEY" --region eu --mode live

# Self-hosted, base URL without /api/v1
lago init --api-key "$LAGO_API_KEY" --region self-hosted --api-url https://lago.example.com --mode test

# Opt in to a once-daily anonymous release check
lago init --api-key "$LAGO_API_KEY" --region us --mode test --update-check
```

```bash whoami
lago whoami
lago whoami --profile eu-prod --output json
lago whoami --output json --query 'resolved_api_url'
```

```bash doctor
lago doctor
lago doctor --output json --query 'checks[].{check: name, detail: detail}'

# Sanitized archive to attach to a support ticket
lago doctor --bundle
lago doctor --bundle-path ./lago-doctor.tar.gz
```

```bash version
lago version
lago version --check            # also report whether a newer release exists
lago version --check --channel beta
```

```bash upgrade

```

## Helpers

### Raw API requests

`lago api METHOD PATH` calls any endpoint with the active profile's credentials, redaction, retries, and output handling. The `/api/v1` prefix is optional and never doubled.

```bash
lago api GET /customers?page=2
lago api GET /api/v1/customers                       # same request
lago api POST /events --data @event.json --idempotency-key event-42
printf '{"event":{"code":"api_calls","external_subscription_id":"sub_1"}}' | lago api POST /events --data -
lago api PUT /invoices/4d904d90-4d90-4d90-4d90-4d904d904d90/finalize --confirm 4d904d90-4d90-4d90-4d90-4d904d904d90
lago api GET /customers -H "X-Trace: qa-run-12"
```

| Flag | Description |
| --- | --- |
| `--data`, `-d` | Request body: inline JSON, `@file`, or `-` for stdin. |
| `--header`, `-H` | Additional request header. Repeatable. |
| `--idempotency-key` | Sets the `Idempotency-Key` header and makes the request retry-safe. |

### Documentation

`lago docs <resource>` opens the API reference for a resource in your browser.

```bash
lago docs customers
lago docs billable-metrics
```

### Aliases

Aliases are stored in the config file under `[aliases]`.

```bash
lago alias set cust "customers"
lago alias set inv-open "invoices list --statuses finalized --payment-statuses pending"
lago alias list
lago alias delete cust

lago cust list --limit 5          # expands to: lago customers list --limit 5
```

### Seed and fixtures

`lago seed demo` creates a metric, a plan, a customer, a subscription, one event, and an invoice preview, all prefixed so they are easy to find and delete.

```bash
lago seed demo
lago seed demo --prefix local-demo --output json
```

`lago fixtures run FILE` executes a YAML scenario: ordered API steps, variable interpolation, values captured from one response and reused in the next. Every step carries its own idempotency key, so a re-run is safe.

<CodeGroup>

```bash Run
lago fixtures run scenario.yaml
lago fixtures run scenario.yaml --var prefix=qa --var currency=EUR
lago fixtures run scenario.yaml --var prefix=qa --dry-run   # print every request, send none
```

```yaml scenario.yaml
version: 1
name: usage-plan
vars:
  prefix: demo
steps:
  - id: metric
    method: POST
    path: /billable_metrics
    idempotency_key: ${prefix}-metric
    body:
      billable_metric:
        name: Demo requests
        code: ${prefix}-requests
        aggregation_type: count_agg
    capture:
      metric_id: billable_metric.lago_id
  - id: plan
    method: POST
    path: /plans
    idempotency_key: ${prefix}-plan
    body:
      plan:
        name: Demo usage plan
        code: ${prefix}-plan
        interval: monthly
        amount_cents: 0
        amount_currency: USD
        pay_in_advance: false
        charges:
          - billable_metric_id: ${metric_id}
            charge_model: standard
            properties:
              amount: "1"
    capture:
      plan_code: plan.code
  - id: customer
    method: POST
    path: /customers
    idempotency_key: ${prefix}-customer
    body:
      customer:
        external_id: ${prefix}-customer
        name: Demo Customer
        currency: USD
    capture:
      customer_id: customer.external_id
  - id: subscription
    method: POST
    path: /subscriptions
    idempotency_key: ${prefix}-subscription
    body:
      subscription:
        external_customer_id: ${customer_id}
        external_id: ${prefix}-subscription
        plan_code: ${plan_code}
```

</CodeGroup>

## Billable metrics

| Command | Description |
| --- | --- |
| `billable-metrics create` | Create a metric. |
| `billable-metrics get <code>` | Retrieve a metric. |
| `billable-metrics list` | List metrics. |
| `billable-metrics update <code>` | Update a metric. |
| `billable-metrics delete <code>` | Delete a metric. Confirmation-gated. |
| `billable-metrics evaluate-expression` | Evaluate a custom expression against a sample event. |

<CodeGroup>

```bash Create
# Count every event
lago billable-metrics create --name Requests --code api_requests --aggregation-type count_agg

# Sum a property, with a filter dimension
lago billable-metrics create \
  --name "Tokens" --code llm_tokens \
  --aggregation-type sum_agg --field-name tokens \
  --filters '[{"key":"model","values":["gpt-4o","claude-sonnet"]}]'

# Persist units across periods (seats, storage)
lago billable-metrics create --name Seats --code seats --aggregation-type unique_count_agg --field-name user_id --recurring true

# Derive units from event properties
lago billable-metrics create \
  --name "Compute hours" --code compute_hours \
  --aggregation-type sum_agg --field-name hours \
  --expression 'round(event.properties.seconds / 3600, 2)'
```

```bash Read
lago billable-metrics get api_requests
lago billable-metrics get api_requests --output json --query 'billable_metric.aggregation_type'
lago billable-metrics list --limit 20
lago billable-metrics list --all --output json | jq -r '.billable_metrics[].code'
```

```bash Update and delete
lago billable-metrics update api_requests --name "API requests"
lago billable-metrics delete api_requests --confirm api_requests
```

```bash Evaluate expression
lago billable-metrics evaluate-expression --input '{"expression":"round(event.properties.seconds / 3600, 2)","event":{"code":"compute_hours","timestamp":1756684800,"properties":{"seconds":"5400"}}}'
```

</CodeGroup>

<CodeGroup>

```bash Create
lago customers create \
  --external-id acme_001 \
  --name "Acme Inc." \
  --email billing@acme.example \
  --currency USD \
  --country US --timezone America/New_York \
  --net-payment-term 30

# Attach to a payment provider connection
lago customers create --external-id acme_001 --name "Acme Inc." \
  --billing-configuration-payment-provider stripe \
  --billing-configuration-payment-provider-code stripe_prod \
  --billing-configuration-sync-with-provider true \
  --billing-configuration-provider-payment-methods '["card","sepa_debit"]'

# Tag test data so it is identifiable in the dashboard and kept off invoices
lago customers create --external-id qa_cust_001 --name "QA Test Company" --currency USD \
  --metadata '[{"key":"mode","value":"test","display_in_invoice":false}]'
```

```bash Read
lago customers get acme_001
lago customers get acme_001 --output json --query 'customer.email'
lago customers get acme_001 --output json --query 'customer.metadata'

lago customers list --limit 5
lago customers list --search-term acme
lago customers list --countries US,CA --currencies USD
lago customers list --metadata[mode] test
lago customers list --output json --query "customers[?starts_with(external_id, 'qa_')].external_id"
lago customers list --all --output json | jq -r '.customers[] | select(.external_id | startswith("qa_")) | .external_id'
```

```bash Usage
# Usage hangs off the customer, keyed by the subscription's external ID
lago customers current-usage acme_001 --external-subscription-id acme_001_pro

lago customers current-usage acme_001 --external-subscription-id acme_001_pro \
  --output json --query 'customer_usage.total_amount_cents'

lago customers current-usage acme_001 --external-subscription-id acme_001_pro \
  --output json --query 'customer_usage.charges_usage[].{metric: billable_metric.code, units: units, amount: amount_cents}'

# One charge, since subscription start
lago customers current-usage acme_001 --external-subscription-id acme_001_pro --charge-code api_requests --full-usage true

# Closed periods
lago customers past-usage acme_001 --external-subscription-id acme_001_pro --periods-count 3

# Projection to period end
lago customers projected-usage acme_001 --external-subscription-id acme_001_pro
```

```bash Related resources
lago customers subscriptions acme_001
lago customers invoices acme_001
lago customers credit-notes acme_001
lago customers applied-coupons acme_001
lago customers payments acme_001
lago customers portal-url acme_001 --output json --query 'customer.portal_url'
lago customers checkout-url acme_001
```

```bash Delete
# Non-interactive: --confirm must equal the identifier

```

<CodeGroup>

```bash Create
lago subscriptions create \
  --subscription-external-customer-id acme_001 \
  --subscription-external-id acme_001_pro \
  --subscription-plan-code pro

# Anniversary billing, starting on a given date
lago subscriptions create \
  --subscription-external-customer-id acme_001 \
  --subscription-external-id acme_001_pro \
  --subscription-plan-code pro \
  --subscription-billing-time anniversary \
  --subscription-subscription-at 2026-10-01T00:00:00Z

lago subscriptions create \
  --subscription-external-customer-id acme_001 \
  --subscription-external-id acme_001_pro \
  --subscription-plan-code pro \
  --subscription-plan-overrides-amount-cents 7900

# Upgrade: same external_id, new plan code
lago subscriptions create \
  --subscription-external-customer-id acme_001 \
  --subscription-external-id acme_001_pro \
  --subscription-plan-code enterprise
```

```bash Read
lago subscriptions get acme_001_pro
lago subscriptions list --external-customer-id acme_001
lago subscriptions list --plan-code pro --status active --all --output json | jq -r '.subscriptions[].external_id'
lago subscriptions charges acme_001_pro
lago subscriptions lifetime-usage acme_001_pro
```

```bash Update
lago subscriptions update acme_001_pro --subscription-name "Acme Pro (annual commit)"
lago subscriptions update acme_001_pro --subscription-ending-at 2027-09-30T23:59:59Z
lago subscriptions override-subscription-charge acme_001_pro api_requests --input '{"charge":{"properties":{"amount":"0.05"}}}'
```

```bash Alerts

```

## Events

| Command | Description |
| --- | --- |
| `events send` | Send one usage event, or stream many from NDJSON with `--file`. |
| `events batch` | Send up to 100 events in one request. |
| `events get <transaction_id>` | Retrieve an event. |
| `events list` | List events. |
| `events estimate-fees` | Estimate the fee for a pay-in-advance charge without recording the event. |
| `events estimate-instant-fees` | Estimate fees for instant charges. |
| `events batch-estimate-instant-fees` | Estimate instant fees for a batch. |

Events are idempotent on `transaction_id`. Sending the same transaction twice records one event, so retries never double-bill. The CLI generates a transaction ID when you omit one and reuses it as the idempotency key.

<CodeGroup>

```bash Send one
lago events send --external-subscription-id acme_001_pro --code api_requests

lago events send \
  --external-subscription-id acme_001_pro \
  --code llm_tokens \
  --transaction-id req_01J8X2Y3Z4 \
  --timestamp 1756684800 \
  --properties '{"tokens":"1523","model":"gpt-4o"}'

# Dynamic pricing: pass the amount your system computed
lago events send --external-subscription-id acme_001_pro --code payments_volume \
  --properties '{"amount":"12000"}' --precise-total-amount-cents 12000.0
```

```bash Stream NDJSON
# One JSON event per line. Missing transaction_ids are generated. Nothing is loaded into memory.
lago events send --file events.ndjson --concurrency 8
cat events.ndjson | lago events send --file -
```

```json events.ndjson
{"external_subscription_id":"acme_001_pro","code":"api_requests","transaction_id":"req_0001","timestamp":1756684800}
{"external_subscription_id":"acme_001_pro","code":"api_requests","transaction_id":"req_0002","timestamp":1756684801}
{"external_subscription_id":"acme_001_pro","code":"llm_tokens","transaction_id":"req_0003","properties":{"tokens":"812","model":"gpt-4o"}}
```

```bash Batch
lago events batch --input @batch.json
lago events batch --events '[{"external_subscription_id":"acme_001_pro","code":"api_requests","transaction_id":"req_0004"},{"external_subscription_id":"acme_001_pro","code":"api_requests","transaction_id":"req_0005"}]'
```

```bash Read
lago events get req_01J8X2Y3Z4
lago events list --external-subscription-id acme_001_pro --code api_requests --timestamp-from 2026-09-01T00:00:00Z --limit 100
```

```bash Estimate
# What would this event cost under a pay-in-advance charge? Nothing is recorded.
lago events estimate-fees --external-subscription-id acme_001_pro --code seats --output json --query 'fees[].amount_cents'
```

</CodeGroup>

## A QA pattern that transfers

Six shapes cover every resource. Swap the noun and the identifier kind:

```bash
lago customers create --external-id qa_cust_001 --name "QA Test Company" --currency USD       # 1. create: identifiers back
lago customers create --external-id qa_cust_001 --name "QA Test Company" --currency USD       # 2. repeat: upsert or clean API error, never a crash
lago customers get qa_cust_001 --output json --query 'customer.email'                         # 3. read + wrapper-aware query
lago customers list --limit 5                                                                  # 4. list
lago customers get does_not_exist_123; echo $?                                                 # 5. 404 names the resource, exit 4
lago customers create --external-id qa_dry_001 --name "Dry Run Co" --currency USD --dry-run   # 6. dry run: exact request, nothing sent
```

Clean up in reverse dependency order: subscriptions, then customers, then plans, then billable metrics. Every delete is confirmation-gated, so a cleanup script passes `--confirm` with the identifier it is deleting.
