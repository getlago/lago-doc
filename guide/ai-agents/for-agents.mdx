Use Lago's public documentation, REST API, CLI, and MCP server with your AI agent. Start with a product description or pricing model; open your application repository when you are ready to implement. The public [Lago plugin](https://github.com/getlago/lago-plugin) offers a guided offline example and implementation workflow for Claude Code and Codex.

## Start with a prompt

Paste this into your coding agent:

```text
Read https://getlago.com/llms.txt and follow the relevant Lago guides for this
project. Use https://swagger.getlago.com/openapi.yaml for exact API fields.
Help me design and implement a billing integration. Ask before live access.
```

Describe what your customers pay for. Your agent can use public documentation to propose the customer identifiers, billable metrics, plans, and subscription lifecycle before connecting to a live environment.

## Model your pricing

Give the agent a product description or pricing page:

```text
We sell an AI research product. Customers pay a subscription with included usage,
then overages. Help me model who pays, what we meter, and how the amount is
calculated in Lago. Identify the smallest integration we can verify.
```

Other starting points:

- **API usage:** "Model a subscription with included API calls and usage overages."
- **Prepaid credits:** "Help me model prepaid usage, wallet consumption, and what my application should do when credit runs out."
- **Existing billing:** "Help me add Lago usage billing to my existing architecture. Identify which system owns subscriptions, invoicing, and payments."

## Implement in your application

Open the application repository and ask:

```text
Implement Lago in this application. Inspect the codebase, propose the smallest
billing slice, and add usage events and tests. Ask before accessing any live
Lago environment.
```

Review the proposed customer identifiers, billable metrics, plans, and subscription lifecycle. Your application should use an official Lago SDK or the REST API. It should not shell out to the CLI or require an MCP server at runtime.

A useful first validation checks the expected charge, retries the same logical event with the same `transaction_id` and explicit `timestamp`, and compares the resulting Lago usage or invoice data with the independently calculated expectation. On organizations using the ClickHouse-based event pipeline, both fields must match for Lago to treat a retry as the same event. A different or omitted timestamp creates a distinct billable event. See [Idempotency and deduplication](/guide/events/ingesting-usage#idempotency-and-deduplication). A successful API response alone does not establish billing correctness.

## Choose how your agent connects

| Tool | Use it for | Requirements |
| --- | --- | --- |
| Lago CLI | Terminal workflows, diagnostics, scripts, and structured billing results | Installed CLI; configured credentials for live requests |
| Product MCP | Read billing data and perform supported operations through connected tools | MCP client, Docker, Lago API key, and target API URL |
| Documentation MCP | Search and retrieve public Lago documentation | Compatible MCP client |
| REST API or SDK | Your application's production integration | Server-side API credentials and the correct regional or self-hosted API URL |

Choose the interface your agent supports. The API, CLI, and MCP work independently; you do not need to install all three. Application code should use the REST API or an official SDK.

### Build with the API or an SDK

Start with the [API reference](/api-reference/intro) and [developer resources](/developers) for supported SDKs. Give your agent the [complete OpenAPI specification](https://swagger.getlago.com/openapi.yaml) for exact fields. Keep credentials server-side and confirm the US, EU, or self-hosted API URL before sending requests.

### Use the CLI or the product MCP

The [Lago CLI](/guide/lago-cli/overview) covers terminal workflows, diagnostics, and scripts. The [product MCP server](/guide/ai-agents/mcp-server) gives an MCP client access to live billing data. Both contact a real Lago organization: set the US, EU, or self-hosted API URL explicitly and keep the API key in your client's secret configuration. Start with a read-only request, such as listing a customer's invoices.

## Give your agent the documentation

Use these sources to keep generated code aligned with Lago’s current API and workflows.

- **Documentation index:** [llms.txt](https://getlago.com/llms.txt)
- **Documentation MCP:** `https://docs.getlago.com/mcp`
- **Complete OpenAPI contract:** [openapi.yaml](https://swagger.getlago.com/openapi.yaml)
- **Developer resources:** [API, SDKs, authentication, and webhooks](/developers)

Configure the documentation MCP as a remote HTTP server in a compatible client. It provides documentation access, not access to your Lago organization.

## Validate before live billing

Keep API keys out of prompts, source control, and browser code. Confirm the organization, API URL, affected records, and expected billing impact before live work. Ask your agent to show the proposed changes before executing financial or destructive operations.

Lago has no built-in sandbox, and naming an organization "test" does not isolate it. Run synthetic tests in a separate Lago Cloud organization or an isolated self-hosted instance. Follow the [integration testing guide](/guide/integration-testing) when validating your own application.

## Optional: install the Lago plugin

The public [Lago plugin](https://github.com/getlago/lago-plugin) packages Lago billing guidance, worked examples, and an implementation workflow for Claude Code and Codex. It is optional; your application uses the REST API or a Lago SDK at runtime.

The plugin supports Claude Code and Codex. Exploring its offline example and designing an integration require no Lago account, API key, CLI, or MCP connection.
