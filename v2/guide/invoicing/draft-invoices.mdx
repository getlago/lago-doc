A draft invoice is an invoice in `draft` status that is not finalized yet. Use the draft window, set by the [grace period](/v2/guide/invoicing/invoicing-settings/grace-period), to recalculate fees after late events, finalize early, or delete an invoice generated by mistake.

The API supports three draft actions:

| Action | Endpoint | Effect |
| --- | --- | --- |
| Refresh | `PUT /invoices/{lago_id}/refresh` | Recalculates fees, taxes and totals. |
| Finalize | `PUT /invoices/{lago_id}/finalize` | Refreshes, then finalizes the invoice. |
| Delete | `DELETE /invoices/{lago_id}` | Removes a draft not synced to an external integration. |

Refresh and finalize support subscription and contract invoices only. Other invoice types return `403`.

## Add late usage to a draft

Send [events](/v2/guide/events/ingesting-usage) with `external_contract_id` and a `timestamp` inside the billing period of the draft, then refresh it.

> Billing period: January 1 to January 31, 2027
> Grace period: 3 days
> Today: February 2, 2027
>
> An event for `contract_example` with a timestamp on January 11 belongs to the January draft. Refresh the draft to see it.

## Refresh a draft invoice

<Tabs>
  <Tab title="Dashboard">
    1. Open the draft invoice; and
    2. Click **Refresh**.
  </Tab>
  <Tab title="API">
    <CodeGroup>
    ```bash Refresh a draft invoice
    LAGO_URL="https://api.getlago.com"
    API_KEY="__YOUR_API_KEY__"
    INVOICE_ID="__YOUR_INVOICE_ID__"

    curl --location --request PUT "$LAGO_URL/api/v2/invoices/$INVOICE_ID/refresh" \
      --header "Authorization: Bearer $API_KEY"
    ```
    </CodeGroup>

    Eligible non-draft invoices return `200` unchanged.
  </Tab>
</Tabs>

## Finalize a draft invoice

Finalize a draft when you have reviewed it and want to bill before the grace period ends. Finalization refreshes the invoice first.

<Warning>
Finalizing turns the draft into a finalized invoice that can be collected. It cannot be reversed. To cancel a finalized invoice later, you must [void it](/v2/guide/invoicing/void). Review the draft before you finalize it in production.
</Warning>

<Tabs>
  <Tab title="Dashboard">
    1. Open the draft invoice;
    2. Click **Finalize**; and
    3. Confirm.
  </Tab>
  <Tab title="API">
    <CodeGroup>
    ```bash Finalize a draft invoice
    LAGO_URL="https://api.getlago.com"
    API_KEY="__YOUR_API_KEY__"
    INVOICE_ID="__YOUR_INVOICE_ID__"

    curl --location --request PUT "$LAGO_URL/api/v2/invoices/$INVOICE_ID/finalize" \
      --header "Authorization: Bearer $API_KEY"
    ```
    </CodeGroup>

    Responses to expect:

    - `200` with the finalized invoice.
    - `200` with the invoice in `pending` status, when this request starts fetching taxes from a tax provider. Finalization completes after the taxes are applied.
    - `403 cannot_finalize_with_pending_taxes`, when provider taxes are already pending.
    - `403`, when the invoice type does not support finalization.
    - `404`, when the invoice is not a draft.
  </Tab>
</Tabs>

## Delete a draft invoice

Delete a draft when the invoice itself is a mistake, for example a duplicate contract or test data. Only draft invoices that are not synchronized to an external integration can be deleted.

<Warning>
Deletion cannot be undone. If the amounts are wrong but the billing is legitimate, fix the usage, refresh the draft and finalize it instead.
</Warning>

<Tabs>
  <Tab title="Dashboard">
    1. Open the draft invoice;
    2. Click the **ellipsis icon** and select **Delete invoice**; and
    3. Confirm.
  </Tab>
  <Tab title="API">
    <CodeGroup>
    ```bash Delete a draft invoice
    LAGO_URL="https://api.getlago.com"
    API_KEY="__YOUR_API_KEY__"
    INVOICE_ID="__YOUR_INVOICE_ID__"

    curl --location --request DELETE "$LAGO_URL/api/v2/invoices/$INVOICE_ID" \
      --header "Authorization: Bearer $API_KEY"
    ```
    </CodeGroup>

    The response returns the invoice with `status: "deleted"`. The invoice object does not expose `deleted_at`.
  </Tab>
</Tabs>

### Delete or void

- **Delete** applies to drafts. The invoice should never have existed.
- **Void** applies to eligible finalized invoices. The invoice was real and stays on record. See [Void invoices](/v2/guide/invoicing/void).
