A payment provider is the PSP that charges your customers, such as Stripe, Adyen or GoCardless. Lago stays payment-processor agnostic: connect the provider you already use, and Lago asks it to collect the invoices of your [contracts](/v2/guide/contracts/overview).

## Connect a customer to a provider

The customer carries its provider settings as top-level fields:

| Field | Meaning |
| --- | --- |
| `payment_provider` | Provider type, for example `stripe`. |
| `payment_provider_code` | Code of the provider connection in your organization. |
| `provider_customer_id` | Customer identifier in the provider, for example `cus_example`. |
| `provider_payment_methods` | Payment methods allowed by the provider. |
| `sync_with_provider` | Whether to create or synchronize the customer with the provider. |
| `sync` | Whether to run provider synchronization before returning the response instead of in a background job. |

<Tabs>
  <Tab title="Dashboard">
    1. Open **Customers** and select the customer;
    2. Click **Edit**;
    3. In **Payment provider**, select the provider connection;
    4. Enter the provider customer ID, or let Lago create the customer in the provider; and
    5. Save.
  </Tab>
  <Tab title="API">
    <CodeGroup>
    ```bash Connect a customer to Stripe
    LAGO_URL="https://api.getlago.com"
    API_KEY="__YOUR_API_KEY__"

    curl --location --request PATCH "$LAGO_URL/api/v2/customers/customer_example" \
      --header "Authorization: Bearer $API_KEY" \
      --header 'Content-Type: application/json' \
      --data-raw '{
        "customer": {
          "payment_provider": "stripe",
          "payment_provider_code": "stripe_main",
          "sync_with_provider": true
        }
      }'
    ```
    </CodeGroup>
  </Tab>
</Tabs>

## Collect a payment

Once a customer is connected, these endpoints drive collection:

| Need | Endpoint | Page |
| --- | --- | --- |
| Capture a payment method | `POST /customers/{customer_external_id}/checkout_url` | [Payment methods](/v2/guide/payments/payment-methods) |
| Retry a failed charge | `POST /invoices/{lago_id}/retry_payment` | [Payment retries](/v2/guide/payments/payment-retries) |
| Send a pay link for one invoice | `POST /invoices/{lago_id}/payment_url` | [Payment retries](/v2/guide/payments/payment-retries) |
| Collect several overdue invoices | `POST /payment_requests` | [Payment requests](/v2/guide/payments/payment-requests) |
| Refund through a credit note | `POST /credit_notes` with `refund_amount_cents` | [Credit notes](/v2/guide/invoicing/credit-notes/overview) |

Provider payments appear in [`GET /payments`](/v2/api-reference/payments/list) with `payment_type: "provider"`, `payment_provider_code` and `provider_payment_id`. When the provider needs the customer to act, for example to authenticate, `next_action` holds the provider instructions.
