An aggregation type defines how a billable metric calculates a quantity from usage events. Choose it based on what you want to measure: the number of actions, distinct users, a total, or a reported value.

For example, use Count to count API calls, Sum to total tokens consumed, or Max to find the highest number of CPUs used.

| Aggregation | `aggregation_type` | What it does | Supports recurring: |
| --- | --- | --- | --- |
| [Count](/v2/guide/billable-metrics/aggregation-types/count) | `count_agg` | Counts matching events. | False |
| [Count unique](/v2/guide/billable-metrics/aggregation-types/count-unique) | `unique_count_agg` | Counts distinct values of an event property. | True |
| [Latest](/v2/guide/billable-metrics/aggregation-types/latest) | `latest_agg` | Uses the most recent value of an event property. | False |
| [Max](/v2/guide/billable-metrics/aggregation-types/max) | `max_agg` | Uses the highest value of an event property. | False |
| [Sum](/v2/guide/billable-metrics/aggregation-types/sum) | `sum_agg` | Adds the values of an event property. | True |
| [Weighted sum](/v2/guide/billable-metrics/aggregation-types/weighted-sum) | `weighted_sum_agg` | Weights each value by how long it applies during the billing period. | True |

Count counts events without reading a numeric property. For other aggregation types, `field_name` identifies the event property to aggregate. See [SQL expressions](/v2/guide/billable-metrics/sql-expressions) for calculating a value from event properties.

With `recurring: true`, the aggregated value carries over between billing cycles. With `recurring: false`, it resets at the end of each cycle.
